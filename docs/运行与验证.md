# 运行与验证

当前版本是本机开发验证PoC，数据保存在 `.local/workstation/`，不会推送到GitHub。真实论文、Agent宿主、远程笔记本与手机通知尚未接入。

需要 Python 3.12+、Git、Node.js 18+。Archify使用固定提交，Python依赖使用带SHA-256的 `requirements.lock`。

## Linux / macOS

在仓库根目录执行：

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

setup会创建独立虚拟环境、校验安装依赖、下载/固定Archify并运行14个控制面测试。start以单进程启动本机服务，浏览器访问本机8765端口。不要用多进程workers或将本版未鉴权API直接暴露到公网。

云环境已经保留 `/workspace/tools/archify` 时，可设置 `THESIS_ARCHIFY_DIR` 指向该目录再执行脚本。脚本支持该覆盖，避免重复下载。

## Windows

在仓库根目录的PowerShell执行：

```powershell
./scripts/setup.ps1
./scripts/start.ps1
```

当前云环境没有Windows专业软件；PowerShell入口已提供，Windows和CAD/TIA等软件的运行状态必须在实际执行机验证。

## 第一条验证路线

1. 建立项目，明确资料为开发样例或真实输入。
2. 建立验证任务链；确认前派发会被服务器拒绝。
3. 确认方案，派发输入清单；查看真实文件、字节数、SHA-256。
4. 由不同身份分别登记工程质量与目标一致性报告。界面是人工登记，不会假装调用了模型。
5. 运行依赖任务，用固定Archify CLI真实生成HTML/SVG。
6. 两项任务通过检查后，用户验收并下载冻结manifest。
7. 用源码测试验证实际缺文件、P0两审、旧版本、锁冲突、重启和依赖失效。

## 模型配置

只有需要真实模型草案任务时才配置环境变量：

- `THESIS_MODEL_BASE_URL`：实际已验证的兼容网关 `/v1` 根端点。
- `THESIS_MODEL_API_KEY`：在运行环境安全配置，不写入Git或聊天。
- `THESIS_RETRY_OWNER`：默认 `gateway`，客户端不叠加重试；明确直连且上游不重试时可选 `client`。
- `THESIS_WORKER_ID`：本机执行身份，默认 `local`。
- `THESIS_DATA_DIR`：可选持久数据目录。

能力别名与岗位映射见 `config/model-bindings.example.json`。实际网关、模型工具调用、上下文覆盖与费用需独立测试；目前测试使用HTTP桩验证重试和格式行为，未调用付费模型。

## 测试

```bash
THESIS_ARCHIFY_DIR=.tools/archify .venv/bin/python -m unittest discover -s tests -v
```

完整测试要求固定Archify工具就绪，缺失不会用skip伪装通过。`scripts/test_runtime_browser.py` 是当前Linux云环境的额外Chromium验证脚本，需已启动服务与Playwright；不属于应用启动依赖。

测试证据位于 `deliverables/v2.0/research/`。SQLite持久化是本机验证范围；远程鉴权、租约心跳、GitHub API同步、手机投递和真实论文检查仍待专项实现。
