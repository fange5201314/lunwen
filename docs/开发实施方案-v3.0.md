# 毕设论文工作站：统一开发实施方案 v3.0

可以进入开发验证阶段。八份原资料、23条111重点记录/22主题、七套融合蓝图，以及新增34页《系统开发任务流转与工具链验证》已经合并为同一条实施路线。当前仓库已有能运行的控制面PoC，尚未完成真实开题与外文交付。

## 1. 定下来的中心和边界

**Workstation Core 是唯一业务控制中心。**它持有项目黑板、确认版本、任务依赖、运行记录、文件哈希、决策、缺陷和验收。经理Agent使用适合规划的模型提出计划、讨论和修复建议；程序校验并执行门禁，模型回答不能直接覆盖状态。

首轮采用 Python FastAPI + SQLite WAL + 本机项目文件目录，便于在现有电脑上验证。多笔记本阶段采用中心持久化服务和按项目绑定的Worker，每个项目固定一台笔记本领取执行；各笔记本保存原生工程与缓存，中心持有统一任务状态。当前只有本机Worker，远程认证、传输与心跳尚未实现，不能把SQLite文件直接放到网络共享盘充当分布式数据库。

Rovai优先验证长期成员/协作宿主接缝；Paperclip保留团队/任务池候选；PI-Desktop和Codeg保留桌面宿主与画布候选。它们通过适配器接入同一业务中心，当前PoC不运行第二个任务控制器。v2.x的Paperclip派发建议保留作比较；本轮实际实现使用Core-local派发，适配器验证后再决定宿主，不把Rovai“已有完整毕设调度接口”当成事实。

接入效率来自稳定边界：通用业务契约自己实现，成熟解析、文档、绘图和专业工具按能力接入；只有需要改产品行为且许可证允许时才做局部二开。多语言和独立进程本身可以共存，源码级复用也可逐模块评估；无需将所有资源改写成一种语言。

## 4. 当前真实实现到哪一步

代码位于 `workstation/`，API及浏览器验证界面已经可启动：

- 项目、worker绑定、方案版本和批准哈希、决策与事件使用SQLite持久化。
- 注册能力和96岗位分开；输入清单、真实文件完整性、固定版本Archify出图、配置网关的目标草案调用使用能力适配器。
- 确认版本、上游检查、执行机归属和排他资源锁共同控制派发；重复派发返回同一个活动run。
- 实际产物回收、大小/SHA-256、运行检查点和错误落盘；进程成功或文件名存在不能直接当用户验收。
- 两类审查分别登记身份、run、plan_version、generation、输入输出哈希；作者/同成员/旧报告被拒收，报告沉默保持待审。
- P0一次补丁后复审；两审仍失败进入本机待处理。Issue本地去重并可导出，尚未创建/关闭远端Issue。
- 人工恢复会记录理由；服务重启保留中断现场和资源锁，人工确认旧进程停止后才能重新领取。
- 任务依赖级的版本失效、有效文件重新验哈希、用户验收与冻结manifest已实现。

审查端点接收外部Worker或用户提供的报告。当前浏览器是人工登记，测试报告由测试驱动输入；没有把它包装成真实模型审查。专业Worker、持续后台自动领取、多设备认证传输、手机通知、真实论文链和段落/对象级影响仍属于后续任务。

API `/api/health` 的能力状态会区分ready与待接入；未配置模型时不会生成假模型回答。原有离线融合实验室仍是交互设计，两者证据口径不同。

## 5. Agent、缺陷与恢复的具体协议

岗位身份Rxxx长期稳定，执行实例与上下文按project/run分离。模型绑定由能力配置决定，换模型不会改任务职责和历史。用于SHA、依赖、锁与文件检查的确定性逻辑不用大模型。

审查缺陷必须提供严重级别、位置、描述与相关证据。P1/P2不阻断一般推进；如果涉及学校必交格式、缺原文、错误数据或强制指标，系统按硬性要求提升为P0。作者只修改列出的位置，已经检查的文件/段落保留；当前PoC控制轮次与版本，真正内容补丁由执行Agent接入后实现。

一审有P0时暂停依赖，产生可处理补丁工单；首轮批准范围内允许一次有限修复。二审仍失败停止自动循环，由你仲裁、补资料或创建新方案。技术故障保存现场等待人工；不能因为API可重试就盲目重放CAD、数据库写入或文档提交。

网关默认拥有全部请求重试，客户端只调用一次；只有明确使用没有重试的直连端点时，客户端才拥有最多3次/90秒的预算。401/403、协议不符、空/错误JSON不循环重试；流式和工具副作用恢复需后续专项接缝验证。

GitHub同步采用Outbox：本地指纹→repo/issue号映射→版本化投影；重复扫描同一个缺陷不创建新Issue。重新检测到新问题时创建新run与检查记录；不得自动覆盖已验收版本。关闭Issue需真实验证通过，commit中出现“Fixes”不代替检查。

## 7. 成本和仍需实际材料的接缝

原整体范围估算约33–52人日，专业软件和多笔记本传输另估。本次PoC已完成的代码不能据此声称全部MVP完工；接缝试验后按真实缺陷与范围重新估算。没有“几百行即可完成整套系统”或固定省70%费用的保证。

模型成本按各能力实际输入/输出Token单价记录；强规划/审查与较经济的制作模型分别评测，不能仅按品牌或价格认定专业能力。外部软件许可、解析GPU、存储和多机运维单独统计。

现在可以开发A2/A3，不需要先补齐所有专业资料。真实模型运行需要已验证网关配置；开题/外文需要一个真实任务书和学校模板；多机阶段需要执行机/网络条件；Windows专业软件按对应链路准备。已有文献库作为可用材料来源，具体自动读取入口和文件授权由实际接缝确认。

## 8. 启动与评估

先读 `docs/运行与验证.md`。Linux使用 `bash scripts/setup.sh`、`bash scripts/start.sh`；Windows提供PowerShell脚本，当前云环境的执行证据是Linux，Windows需现场复验。

从浏览器建立开发样例→建立验证任务→确认方案→派发输入清单→分别登记两类检查→运行真实Archify→用户验收manifest。再用缺失文件、旧报告、P0、方案改版和重启验证异常路径。

用于生产毕设之前，要通过B批次真实文档闭环。离线原型用于评估操作方式，运行核心用于验证状态、接口和工具链；当前两者都已保留在同一仓库。
